# معمارية تكوين (Takween Architecture)

## نظرة عامة
MVP الحالي مبني كخط أنابيب بسيط:

1. **CLI Layer** (`المصدر/الرئيسية.baa`)
2. **Config Parser** (`المصدر/محلل_النصوص.baa`)
3. **Command Executor** (`المصدر/منفذ_الأوامر.baa`)

## المسؤوليات
- `الرئيسية.baa`
  - قراءة الأمر من `معاملات`.
  - مطابقة الأمر العربي/الإنجليزي.
  - توجيه التنفيذ للدالة المناسبة.

- `محلل_النصوص.baa`
  - اكتشاف صيغة 0.1 أو `takween-manifest-v1` دون fallback صامت.
  - التحقق الصارم من الأقسام والمفاتيح والأنواع والقيم.
  - الإبلاغ المبكر عن الأخطاء مع رقم السطر.

- `منفذ_الأوامر.baa`
  - تنفيذ `تهيئة` وإنشاء القالب.
  - بناء متجهات argv مملوكة وتشغيلها عبر Process API في Baa.
  - جمع مصادر/تضمينات اعتماديات المسار المتعدية في خطة المصرّف.
  - استدعاء parser قبل أوامر البناء/التشغيل.

## حدود المرحلة الحالية
- parser لا يبني AST مستقل؛ يبني نموذج تكوين صارم (Config Model) للاستخدام المباشر.
- build pipeline الأساسي مفعل (parse -> validation -> Baa incremental build -> compile/link).
- `check` يمرر عقد `diagnostics-json-v1`، وbuild يستهلك cache وبيان schema 1.
- `run` مفعل (build ثم execute) و`clean` يطبق فحوص أمان قبل الحذف.
- executor لا يستخدم shell؛ build/check/run تمرر argv مباشرة، وinit/clean يستخدمان
  واجهات مجلدات UTF-8 المحمية من Baa. نموذج التنفيذ نفسه معد لـ Windows وLinux.
- v1 التنفيذي الحالي يدعم هدفا واحدا ومسارات ملفات صريحة واعتماديات path؛ globs
  والأهداف المتعددة وGit/registry والقفل لم تنفذ بعد وتفشل أو تبقى خارج الخطة بوضوح.

## المعمارية المستهدفة

1. **Manifest Parser** يبني نموذجا typed بلا side effects.
2. **Resolver** يحل الأهداف والاعتماديات وينتج lock graph حتميا.
3. **Planner** يحول النموذج إلى DAG وخطوات Baa موصوفة.
4. **Executor** يشغل argv مباشرة ويجمع stdout/stderr/exit code دون shell.
5. **Reporter** يعرض العربية للبشر وJSON لـ Qalam وCI.
6. **Cache** يستخدم build manifest وhash المحتوى ولا يخمن اعتماديات من النص.

يجب أن تبقى هذه الطبقات قابلة للاختبار مستقلة؛ Qalam يستهلك CLI/JSON ولا يربط
بنموذج parser الداخلي.

## واجهة داخلية (Current Internal API)
- `صحيح تحليل_ملف_تكوين(نص مسار).`
- `صحيح تنفيذ_تهيئة().`
- `صحيح تنفيذ_بناء().`
- `صحيح تنفيذ_فحص().`
- `صحيح تنفيذ_تشغيل().`
- `صحيح تنفيذ_تنظيف().`

## مبادئ التصميم
- Fail-Fast لأي خطأ في ملف الإعداد.
- عقود واضحة للأوامر قبل التوسع في الميزات.
- عزل side effects في executor.
