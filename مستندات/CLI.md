# عقد CLI (Takween CLI Contract)

## الأوامر الرسمية (MVP)
- `تكوين تهيئة`
- `تكوين init`
- `تكوين بناء`
- `تكوين build`
- `تكوين خطة --جسون [اسم_هدف]`
- `تكوين plan --json [target_name]`
- `تكوين فحص`
- `تكوين check`
- `تكوين اختبار [اسم_هدف]`
- `تكوين test [target_name]`
- `تكوين أهداف --جسون`
- `تكوين targets --json`
- `تكوين مساحة --جسون`
- `تكوين workspace --json`
- `تكوين تشغيل`
- `تكوين run`
- `تكوين تنظيف`
- `تكوين clean`
- `تكوين --إصدار`
- `تكوين --version`

> alias متوافق: `takween ...`

تقبل أوامر `بناء/build` و`فحص/check` و`تشغيل/run` و`اختبار/test` الخيار
`--مقفل` مع اسم هدف اختياري بأي ترتيب، و`--نمط <اسم_عربي>` لاختيار profile.
يبقى `--locked` و`--profile` aliasين للتوافق الآلي. يقبل `خطة/plan` الخيارين
نفسيهما، ويتطلب `--جسون` أو alias التوافق `--json`.
يدعم `بناء/اختبار` كذلك `--حزمة <اسم_عربي>` أو `--كل_الحزم`، مع
`--package/--all-packages` للتوافق فقط.
تقبل أوامر `بناء/فحص/تشغيل/اختبار/تنظيف` كذلك
`--ملف_أحداث <مسار>` لكتابة `takween-build-events-v1` كـJSONL مستقل عن
المخرجات البشرية. يبقى `--events-file` alias توافق آلي فقط.

## السلوك المتوقع

### `تهيئة / init`
- ينشئ قالب مشروع مبدئي:
  - `مشروع.تكوين`
  - `المصدر/`
  - `المصدر/الرئيسية.baa`

### `بناء / build`
- يقرأ `مشروع.تكوين`.
- يكتشف صيغة 0.1 أو `takween-manifest-v1` تلقائيا وبصرامة.
- يفشل مباشرة عند أي خرق للمواصفة.
- يقبل جذور `.baa` و`.نظم` في البيان نفسه.
- حذف `المجمع` أو كتابة `المجمع = "نظم"` في `[البناء]` يجعل Baa يولد
  التجميع العربي ويستدعي الأمر `نظم` من `PATH`; المستخدم لا يكتب اسم GAS
  أو Nazm اللاتيني. `المجمع = "غاز"` هو الرجوع الصريح.
- ينفّذ بناء فعلي عبر `baa` ويولّد الناتج حسب `المخرج + الاسم + النوع`.
- يفعّل `--incremental` ويكتب الكاش في `المخرج/.takween-cache`.
- يكتب `المخرج/build-manifest.json` وفق schema 1 من Baa.
- يكتب `المخرج/build-cache.json` وفق `takween-content-cache-v1`، ومفتاح
  SHA-256 ودليله canonical تحت `.takween-cache/takween-content`.
- يطلب بصمة `nazm-api-v1` الصالحة من بيان Baa ويضيفها إلى الهوية؛ أي تغير في
  إصدار نظم أو هضم قدراته ينتج مفتاحا جديدا.
- hit في هذا الإيصال يعني أن كل وحدات Baa و`.نظم` القابلة لإعادة الاستخدام
  أصابت كاش الكائنات؛ الربط ينفذ ويظهر `link_executed=true`.
- يطبق النمط المختار: `تطوير` مدمج كـ`-O1 --verify`، و`إصدار`
  كـ`-O2 --verify`، أو نمط عربي مخصص typed من البيان.
- يحل `يعتمد_على` كـDAG أهداف؛ يضيف مكتبات الإغلاق المتعدي بترتيب
  dependency-first ويرفض الدورة أو edge غير المكتبة.
- يضيف مصادر ومسارات تضمين اعتماديات `المسار` وGit المتعدية إلى استدعاء Baa نفسه.
- يكتب `تكوين.قفل` وفق `takween-lock-v1` لـ v1، مع هدف Baa والمصادر وعلاقات
  الحزم وcommit الدقيق، بترتيب حتمي وUTF-8/LF.
- يجلب Git إلى `.takween/packages/<commit>` ويعيد استخدام checkout المثبت دون
  الاتصال بالمصدر إذا كان cache صالحا.
- لا يمرر أي سطر أوامر إلى shell؛ كل وسيط يحتفظ بحدوده النصية.

### `فحص / check`

- يقرأ الملف نفسه ويطبق فحوص المسار والأعلام نفسها دون بناء الناتج.
- يستدعي Baa عبر `--check --diagnostics=json`.
- جذور `.نظم` المباشرة تعيد حاليا غير مدعوم `3` لأن Nazm لا يوفر بعد
  عقد تشخيصات JSON يمكن دمجه دون تحليل النص.
- يمرر `diagnostics-json-v1` كما هو ليستهلكه Qalam وCI دون تحليل النص البشري.
- يحل الاعتماديات ويكتب القفل دون طباعة نجاح إضافية تكسر JSON التشخيصات.
- مع `--locked`: يحل الخطة نفسها ويقارنها بالقفل الموجود دون استبداله؛ القفل
  المفقود أو القديم خطأ مصدر/مشروع بكود `1`.

### `خطة --جسون / plan --json`

- يحلل البيان ويكتشف الهدف ويحل الاعتماديات، ثم يستدعي المخطط النقي.
- يخرج وثيقة `takween-build-plan-v1` واحدة تتضمن المشروع والهدف وprofile
  المملوك وargv الدقيقة.
- يتضمن `target_order` إغلاق DAG الانتقائي بترتيب المكتبات ثم الهدف.
- لا ينشئ مجلد المخرج ولا ينفذ Baa للبناء.
- يثبت `--assembler=nazm` إذا لم يحدد البيان مجمعا أو اختار `نظم`،
  ويثبت `--assembler=gas` فقط عند `المجمع = "غاز"`.
- مع نفس البيان والهدف ومعلومات Baa وحل الاعتماديات، يخرج بايتات متطابقة.
- `--نمط <اسم>` يتجاوز اختيار `[البناء]` للعملية الحالية؛ الاسم اللاتيني أو
  النمط العربي غير المعرّف أو الخيار المكرر يفشل قبل التنفيذ.
- التفاصيل المعيارية في [`BUILD_PLAN_V1.md`](BUILD_PLAN_V1.md).

### `تشغيل / run`
- يستدعي build أولاً.
- عند نجاح build: يشغّل الناتج.
- يُرجع كود خروج البرنامج الناتج كما هو.

### `اختبار / test`

- دون اسم هدف: يبني ويشغل كل أهداف النوع `اختبار` بالترتيب الوارد في البيان.
- مع اسم هدف: يتحقق من أنه هدف `اختبار` ثم يبنيه ويشغله وحده.
- يتوقف عند أول كود خروج غير صفري ويعيده كما هو.
- يقبل `--locked` قبل اسم الهدف أو بعده ويطبق التحقق نفسه على كل هدف.

### `--locked`

- متاح لـ `build/check/run/test` فقط.
- يتحقق من المشروع والهدف والحزم واختيارات archive وSHA-256 الحالية مقابل
  `تكوين.قفل` الحتمي.
- لا ينشئ قفلا مفقودا ولا يحدّث قفلا قديما، ويحذف مرشح المقارنة المؤقت دائما.
- لا يعني `offline` وحده؛ اعتماديات الإصدار الحالية محلية أصلا، أما Git فقد
  يتصل بمصدره إذا لم يكن checkout المثبت موجودا في cache.

### `أهداف --جسون / targets --json`

- يخرج `takween-targets-v1` فقط دون تحليل نص بشري.
- كل سجل يثبت `name`, `kind`, `status`, `buildable`, `runnable`, و`test`.
- هدفا `تنفيذي` و`اختبار` حالتهما `ready`؛ نوع `مكتبة` معلن حاليا كـ`unsupported`.

### `مساحة --جسون / workspace --json`

- يعيد `takween-workspace-v1` بأسماء الحزم ومساراتها وترتيبها وقدرة الاختبار.
- لا يبني الجذر أو الأعضاء ولا يكتب lock/cache.
- aliases الإنجليزية للتوافق الآلي فقط؛ الصيغة القياسية عربية.

### اختيار حزم مساحة العمل

```text
تكوين بناء --حزمة <اسم_عربي>
تكوين بناء --كل_الحزم
تكوين اختبار --حزمة <اسم_عربي>
تكوين اختبار --كل_الحزم
```

- `--نمط` و`--مقفل` يمران لكل عضو.
- لا يختلط selector الحزمة مع اسم هدف.
- all-build ينفذ الأعضاء بترتيب التصريح؛ all-test يتجاوز العضو بلا اختبارات.
- تفاصيل العقد: [`WORKSPACE_V1.md`](WORKSPACE_V1.md).

### `تنظيف / clean`
- يحذف مخرجات البناء فقط (مثل `بناء/`).
- يرفض المسارات غير الآمنة (`.`, الجذر, أو أي مسار يحتوي `..`).
- لا يحذف `تكوين.قفل` أو `.takween/packages` لأنهما حالة resolution/cache لا ناتج بناء.

### `--ملف_أحداث <مسار>`

- متاح لـ`build/check/run/test/clean`، وبأي ترتيب مع خيارات الهدف المدعومة.
- يفرغ الملف ثم يكتب سطرا JSON كاملا لكل بداية/نهاية عملية ومرحلة وهدف وحزمة،
  ويسجل الآثار المنتجة.
- لا يغير `stdout` أو `stderr` ولا يتطلب تحليل الرسائل العربية.
- العقد المعياري والترتيب وسياسة الانقطاع في
  [`BUILD_EVENTS_V1.md`](BUILD_EVENTS_V1.md).

### `--إصدار / --version`

- يطبع إصدار CLI بصيغة ثابتة مثل `تكوين 0.1.0`.
- يجب أن يطابق إصدار المصدر وملف `dist/VERSION.txt` ومعامل packaging.

## أكواد الخروج (Exit Codes)

تستخدم أوامر تكوين تصنيف `compiler-cli-v1` نفسه، وتحافظ أوامر
`check/build/run/test` على كود Baa غير الصفري دون طيه إلى خطأ عام:

- `0`: نجاح.
- `1`: خطأ في المصدر أو المشروع أو البيان.
- `2`: استدعاء غير صالح أو أمر/وسائط غير صحيحة.
- `3`: هدف أو نمط أو ميزة غير مدعومة.
- `4`: فشل أداة أو backend أو process أو نظام الملفات/المخرجات.
- `5`: خطأ داخلي أو خرق invariant.

بعد نجاح مرحلة البناء، يعيد `run` و`test` كود البرنامج الناتج كما هو. هذا الكود
يمثل البرنامج لا المصرّف، لذلك يجب على المستهلك ربط التصنيف بمرحلة العملية، وألا
يحلل نص الرسالة البشرية لاستنتاج النوع.

## رسائل المساعدة
عند عدم تمرير أمر أو تمرير أمر غير معروف، يجب عرض سطر استخدام واضح يتضمن الأسماء العربية والإنجليزية.
