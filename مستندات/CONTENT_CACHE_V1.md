# عقد `takween-content-cache-v1`

## الغرض

يمتلك Baa كاش الكائنات لكل وحدة ترجمة، ويمتلك `build-manifest` قائمة
الاعتماديات وتجزئاتها. لا يكرر تكوين هاتين المسؤوليتين. يبني تكوين فوقهما هوية
محتوى واحدة للمشروع المختار، ويكتب إيصالا يوضح هل كانت كل وحدات Baa قابلة
لإعادة الاستخدام وهل أصابت الكاش.

هذا العقد كاش مراحل ترجمة الكائنات، وليس وعدا بتجاوز الربط. في الإصدار الأول
ينفذ Baa والربط في كل build، بينما يعيد Baa استخدام الكائنات المطابقة. يسجل
الإيصال لذلك:

```json
{
  "schema_version": "takween-content-cache-v1",
  "key": "64-hex-sha256",
  "scope": "baa-object-units",
  "compiler_version": "0.6.0",
  "baa_target": "x86_64-linux",
  "project_target": "تطبيقي",
  "profile": {
    "name": "تطوير",
    "optimization": 1,
    "verify": true
  },
  "lock_sha256": "64-hex-sha256",
  "units": 3,
  "cache": {
    "reusable": true,
    "hit": true
  },
  "link_executed": true
}
```

## اشتقاق المفتاح

ينشئ تكوين تمثيلا نصيا canonical يبدأ بـ`takween-content-key-v1` ثم يضيف،
بالترتيب:

1. اسم الهدف المختار وترتيب إغلاق DAG.
2. اسم النمط وقيمتي التحسين والتحقق المملوكة داخل خطة البناء.
3. argv الثابتة من `takween-build-plan-v1`، مع حذف مسارات الكاش وبيان Baa
   والناتج لأنها مواقع تخزين وليست مدخلات دلالية.
4. SHA-256 لكل جذر مصدر `.baa` أو `.نظم` في الخطة.
5. SHA-256 الكامل لـ`تكوين.قفل`، أو `-` للبيان القديم الذي لا يملك قفلا.
6. حقول Baa الثابتة: schema، إصدار المصرّف، الهدف، mode، المجمع، التحسين،
   فحوص وقت التشغيل، ونوع/مجمع كل وحدة.
7. تجزئات `units[].dependencies[]` بترتيبها في `build-manifest`، ومعها
   SHA-256 يعيد تكوين حسابه من المسار canonical ولا يسجل المسار نفسه.

لا تدخل `source` و`output` المطلقة، ولا cache slot/reason/hit، في المفتاح.
تعامل تجزئة اعتمادية Baa كقيمة opaque صالحة للعقد وتحتفظ بها للتوافق، لكن
هوية المحتوى تعتمد أيضا SHA-256 الكامل الذي يحسبه `baalib` للمصدر أو الرأس.
المفتاح النهائي وتجزئة القفل كذلك SHA-256 من 64 خانة.

تغيير أي من إصدار المصرّف أو الهدف أو الأعلام أو ترتيب المدخلات أو محتوى مصدر
أو رأس أو اختيار الحزم يغير المفتاح. إعادة build بلا تغيير تحفظ المفتاح نفسه.

## الملفات

بعد build ناجح يكتب تكوين:

- `المخرج/build-cache.json`: حالة آخر build، وتتغير قيمة `cache.hit`.
- `المخرج/.takween-cache/takween-content/<key>.json`: هوية مستقرة بلا حالة
  hit أو وقت.
- `المخرج/.takween-cache/takween-content/<key>.key`: المدخل canonical الذي
  أعطى المفتاح، لفحص CI والتشخيص.
- `المخرج/.takween-cache/takween-content/key-input.txt`: نسخة العمل الأخيرة
  قبل حساب SHA-256.

لا توجد طوابع زمنية، ولا command strings، ولا تحليل للرسائل البشرية.

## معنى الحالة

- `reusable=true`: كل الوحدات في بيان Baa تعلن `cache.enabled=true`.
- `hit=true`: كل الوحدات القابلة لإعادة الاستخدام تعلن hit في الاستدعاء
  الحالي.
- وجود وحدة `.نظم` لا يدعم Baa كاشها بعد يجعل `reusable=false` و`hit=false`
  بوضوح؛ لا يسجل تكوين إصابة زائفة ولا يعود إلى GAS.
- الأعلام التي يتعمد Baa معها تجاوز الكاش، ومنها تحقق IR الحالي، تسجل كذلك
  `reusable=false`. يمكن لنمط typed بلا تحقق استخدام الكاش؛ يبقى اسم النمط
  وقيمة التحقق داخل المفتاح فلا تختلط المخرجات.
- `link_executed=true`: الربط نفذ فعلا. تخطي الربط أو استعادة executable
  يحتاج عقد artifact مستقل في إصدار لاحق.

## الفشل

بعد نجاح Baa، يعد غياب `build-manifest` أو نقص حقوله الثابتة أو فشل كتابة
الإيصال فشل أداة بكود `4`. لا يعلن تكوين نجاح build بلا إيصال cache صالح.
