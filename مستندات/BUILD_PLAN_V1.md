# عقد `takween-build-plan-v1`

## الغرض

يفصل هذا العقد وصف بناء المشروع عن تنفيذ المصرّف. يستهلك مخطط تكوين نموذج
البيان بعد التحليل ومعلومات الهدف ووسائط الاعتماديات بعد الحل، ثم يعيد خطة argv
مملوكة وحتمية. لا يشغّل المخطط عملية، ولا ينشئ مجلدا، ولا يكتب ملفا أو قفلا،
ولا يجلب اعتمادية.

الأمر المخصص للفحص:

```text
تكوين خطة --جسون [اسم_هدف]
```

يعيد وثيقة JSON واحدة ولا ينفذ خطوة Baa الموصوفة. يقبل `--مقفل/--locked`؛
الخيار المقفل يجعل مرحلة الحل السابقة للمخطط تتحقق من القفل دون استبداله.
يبقى `--json` alias توافقيا للأتمتة، ولا يحتاج المستخدم إلى كتابة صيغة لاتينية.

## حدود المراحل

```text
تحليل البيان
  -> ترتيب DAG الأهداف
  -> اكتشاف الهدف
  -> حل الاعتماديات والقفل
  -> مخطط نقي
  -> takween-build-plan-v1
  -> تجهيز مجلد المخرج
  -> تنفيذ argv
```

مرحلة الاكتشاف والحل قد تحدث ملفاتها المعتادة تحت `.takween/plan-info` وتتحقق من
`تكوين.قفل`. هذه آثار resolver وليست آثار المخطط. إنشاء الخطة نفسها لا ينشئ
المخرج ولا يستدعي Baa للبناء.

## الصيغة

```json
{
  "schema_version": "takween-build-plan-v1",
  "operation": "build",
  "project": "تطبيقي",
  "target": "تطبيقي",
  "profile": {
    "name": "تطوير",
    "optimization": 1,
    "verify": true
  },
  "target_order": [
    "هندسة",
    "تطبيقي"
  ],
  "argv": [
    "baa",
    "./المصدر/الرئيسية.baa",
    "./المصدر/هندسة.baa",
    "--assembler=nazm",
    "-O1",
    "--incremental",
    "--cache-dir",
    "بناء/.takween-cache",
    "--emit-build-manifest",
    "بناء/build-manifest.json",
    "-o",
    "بناء/تطبيقي.exe"
  ]
}
```

الحقول:

- `schema_version`: ثابت بالقيمة `takween-build-plan-v1`.
- `operation`: العملية الموصوفة؛ القيمة الحالية `build`.
- `project`: هوية المشروع العربية من البيان.
- `target`: هوية الهدف العربية المختارة.
- `profile`: إيصال مملوك للقيم المحلولة؛ `name` عربي، و`optimization` من
  `0..2`، و`verify` منطقي.
- `target_order`: إغلاق DAG الانتقائي بترتيب dependency-first؛ آخر عنصر هو
  الهدف المختار، وكل مكتبة تظهر مرة واحدة.
- `argv`: الوسائط المملوكة بالترتيب الدقيق الذي سيستهلكه Process API.

## الحتمية والملكية

- المدخلات المتساوية تعني نفس البيان والهدف ومعلومات Baa وحل الاعتماديات.
- مع هذه المدخلات ينتج المخطط JSON مطابقا بايتيا وترتيب argv ثابتا.
- تنسخ الخطة كل وسيط؛ لا تستعير نصا من parser أو resolver.
- تملك الخطة `target_order` كذلك، فلا تعتمد الوثيقة على حالة parser مستعارة.
- تملك الخطة بيانات `profile` كذلك؛ اختيار CLI أو البيان لا يبقى مرجعا مستعارا.
- يضاف اختيار المجمع دائما. إذا لم يحدد البيان `المجمع` تثبت الخطة
  `--assembler=nazm`، وهو الافتراضي الإنتاجي المتفق عليه، حتى لا تعتمد
  الحتمية على default خارجي متغير. `المجمع = "نظم"` ينتج الاختيار نفسه،
  و`المجمع = "غاز"` ينتج `--assembler=gas` للرجوع الصريح.
- لا توجد command string ولا shell quoting؛ كل عنصر في `argv` حد مستقل.
- المستهلك لا يعيد تفسير عناصر `argv` كنص shell.

## الاستقرار

أي تغيير في أسماء الحقول أو معناها أو ترتيب الخطة يحتاج إصدار schema جديدا.
إضافة حقول اختيارية متوافقة ممكنة داخل v1، لكن `argv` يبقى المصدر التنفيذي
المرجعي. يبني [`takween-content-cache-v1`](CONTENT_CACHE_V1.md) فوق الخطة
بعد التنفيذ ولا يغير ملكيتها أو نقاء المخطط.
